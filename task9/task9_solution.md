### Настройка чтения с реплик и консистентность

---

#### **1. Общие принципы выбора**
- **Primary-чтение** требуется для операций, где:
  - Критична **сильная консистентность** (финансовые транзакции, изменение состояния).
  - Риск бизнес-потерь из-за устаревших данных (продажа недоступного товара).
  - Пользователь ожидает мгновенного отражения изменений (актуальный статус заказа).
- **Secondary-чтение** допустимо для:
  - Не критичных к задержке операций (просмотр каталога).
  - Аналитических и фоновых задач.
- **Допустимая задержка репликации**:
  - **Secondary**: 1-5 секунд для большинства операций.
  - **Primary**: Задержка не допускается (требуется немедленная консистентность).

---

#### **2. Таблица операций чтения**

| Коллекция | Операция чтения                               | Источник | Допустимая задержка | Обоснование |
|-----------|-----------------------------------------------|----------|---------------------|-------------|
| **products** | Поиск товаров по категориям и фильтрация по цене (каталог) | Secondary | ≤ 5 сек | Пользователь не заметит задержки в отображении новых/измененных товаров. Низкий бизнес-риск при устаревании данных. |
|           | Отображение описания товара на странице продукта | Secondary | ≤ 1 сек | Цена и описание редко меняются в реальном времени. Кратковременная задержка не критична для UX. |
|           | Проверка остатков при добавлении в корзину/оформлении заказа | **Primary** | 0 мс | Риск продажи недоступного товара. Требуется актуальное состояние остатков для атомарного списания. |

---

#### **3. Описание допустимой задержки репликации**
- **Secondary-чтение**:
  - **≤ 1 сек**: Страницы товаров, история заказов (пользовательский интерфейс).
  - **≤ 5 сек**: Каталог, аналитика.
  - **≤ 60 сек**: Фоновые задачи (очистка корзин).
- **Primary-чтение**: Задержка не допускается. Все операции используют `readPreference=primary`.

---

#### **4. Обоснование выбора**

**Коллекция `products`**:
- **Secondary для каталога**:
  Частота обновлений остатков высока, но пользователь не проверяет наличие товара в момент просмотра каталога. Риск продажи недоступного товара минимизируется **проверкой остатков на Primary при оформлении заказа**.
  *Пример*: Пользователь видит "Смартфон X в наличии" в каталоге (secondary), но при нажатии "Купить" система проверяет остатки на primary и блокирует заказ, если товара нет.

- **Primary для проверки остатков**:
  Бизнес-логика требует атомарности: нельзя допустить продажу товара с отрицательными остатками. Консистентность важнее производительности.

**Коллекция `orders`**:
- **Secondary для истории заказов**:
  Пользователи редко заходят в личный кабинет сразу после оформления заказа. Задержка в 2 сек не нарушит UX, но снизит нагрузку на primary.
  *Исключение*: После успешного платежа пользователь перенаправляется на страницу заказа, где данные читаются с primary.

- **Primary для статуса заказа**:
  Если статус "Отменен" или "Доставлен" отобразится с задержкой, пользователь может повторно запросить доставку или обратиться в поддержку. Это увеличит операционные издержки.

**Коллекция `carts`**:
- **Только Primary**:
  Корзина — высокочастотная операция. Пользователь ожидает мгновенного отражения действий (добавление/удаление товара). Слияние корзин требует атомарности: если гостевая корзина прочитана с secondary с задержкой, товары могут быть потеряны при слиянии.
  *Пример сценария*:
  1. Гость добавил товар в корзину (запись на primary).
  2. Сразу после этого залогинился.
  3. При слиянии система прочитала гостевую корзину с secondary, где запись еще не реплицировалась.
  4. Товары из гостевой корзины не добавлены в пользовательскую → **потеря данных**.

---

#### **5. Примеры настройки в MongoDB**
```javascript
// Чтение с primary (дефолтное поведение)
db.products.findOne(
  { _id: productId },
  { readPreference: "primary" } // Явное указание не обязательно
);

// Чтение с secondary для каталога
db.products.find(
  { category: "electronics", price: { $lte: 50000 } },
  { readPreference: "secondaryPreferred" } // Если secondary недоступен — читаем с primary
);

// Настройка maxStalenessSeconds для secondary (ограничение задержки)
db.orders.find(
  { user_id: userId },
  { readPreference: { mode: "secondary", maxStalenessSeconds: 2 } }
);
```
