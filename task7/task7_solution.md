### Проектирование схем коллекций и стратегии шардирования для MongoDB

---

#### **1. Коллекция `products`**

**Схема документа**:
```javascript
{
  _id: ObjectId,          // Уникальный ID товара
  name: String,           // Наименование товара
  category: String,       // Категория (электроника, книги и т.д.)
  price: Number,          // Цена
  stock: {                // Остатки по геозонам (динамические ключи)
    "Moscow": 50,         // Пример: { "geozone_name": quantity }
    "Ekaterinburg": 20
  },
  attributes: {           // Дополнительные атрибуты
    color: String,
    size: String,
    // ... другие атрибуты
  }
}
```

**Шард-ключ**: `{ _id: "hashed" }`
**Стратегия шардирования**:
- Хеширование по `_id` обеспечивает **равномерное распределение данных** и предотвращает hotspot'ы для популярных товаров.
- **Обоснование**:
  - Основная операция — обновление остатков для конкретного товара в определённой геозоне. Локализация данных по `_id` гарантирует атомарность операций (`$inc` для вложенных полей `stock.<geozone>`) без межшардных запросов.
  - Поиск по категориям и ценам требует scatter-gather-запросов, но это компенсируется редкостью таких операций по сравнению с частыми обновлениями остатков.
  - Хеширование предотвращает дисбаланс при неравномерной популярности товаров (например, "Смартфон X" vs "Книга Y").

**Пример команд MongoDB**:
```javascript
// Включение шардинга для БД
sh.enableSharding("mobile_world");

// Шардирование коллекции products
sh.shardCollection("mobile_world.products", { "_id": "hashed" });

// Индексы для оптимизации запросов
db.products.createIndex({ category: 1, price: 1 }); // Для поиска по категории и цене
```

#### **2. Коллекция `orders`**

**Схема документа**:
```javascript
{
  _id: ObjectId,          // Уникальный ID заказа
  user_id: ObjectId,      // ID клиента
  order_date: ISODate,    // Дата и время оформления
  items: [                // Список товаров в заказе
    {
      product_id: ObjectId,
      price: Number,     // Цена на момент заказа
      quantity: Number
    }
  ],
  status: String,         // "pending", "shipped", "delivered"
  total_amount: Number,   // Общая сумма заказа
  geozone: String         // Геозона (Moscow, SPb и т.д.)
}
```

**Шард-ключ**: `{ user_id: "hashed" }`
**Стратегия шардирования**:
- Хеширование по `user_id` обеспечивает **локальность данных для одного пользователя**.
- **Обоснование**:
  - Основные операции — создание заказа и поиск истории заказов по `user_id`. Шардирование по этому ключу направляет все операции для пользователя на один шард, минимизируя latency.
  - Геозона не включена в шард-ключ, так как заказы одного пользователя обычно привязаны к одной геозоне, а распределение по `user_id` равномернее.
  - Создание заказа с одновременным списанием остатков (в коллекции `products`) не зависит от шардинга `orders`, так как это транзакция на уровне приложения.

**Пример команд MongoDB**:
```javascript
// Шардирование коллекции orders
sh.shardCollection("mobile_world.orders", { "user_id": "hashed" });

// Индексы для оптимизации запросов
db.orders.createIndex({ user_id: 1, order_date: -1 }); // История заказов
db.orders.createIndex({ geozone: 1, status: 1 });      // Аналитика по геозонам
```

#### **3. Коллекция `carts`**

**Схема документа**:
```javascript
{
  _id: ObjectId,                  // Уникальный ID корзины
  user_id: ObjectId,              // ID пользователя (null для гостей)
  session_id: String,             // ID сессии для гостей
  routing_key: String,            // Составной ключ: "user_<id>" или "session_<id>"
  items: [                        // Товары в корзине
    { product_id: ObjectId, quantity: Number }
  ],
  status: String,                 // "active", "ordered", "abandoned"
  created_at: ISODate,            // Время создания
  updated_at: ISODate,            // Время последнего обновления
  expires_at: ISODate             // TTL для автоматической очистки
}
```

**Шард-ключ**: `{ routing_key: "hashed" }`
**Стратегия шардирования**:
- **Составной ключ `routing_key`**:
  - Для гостей: `routing_key = "session_" + session_id`.
  - Для пользователей: `routing_key = "user_" + user_id.toString()`.
- **Обоснование**:
  - Обеспечивает **быстрый доступ** к корзинам по `session_id` (гости) и `user_id` (авторизованные) через единый шард-ключ.
  - Операции слияния корзин (гость → пользователь) требуют межшардных запросов, но они редки по сравнению с операциями чтения/записи.
  - TTL-индекс на `expires_at` эффективно работает при равномерном распределении корзин.
  - Префиксы (`user_`, `session_`) предотвращают коллизии ID.

**Пример команд MongoDB**:
```javascript
// Создание TTL-индекса для автоматической очистки
db.carts.createIndex({ expires_at: 1 }, { expireAfterSeconds: 0 });

// Шардирование коллекции carts
sh.shardCollection("mobile_world.carts", { "routing_key": "hashed" });

// Индексы для операций
db.carts.createIndex({ user_id: 1, status: 1 });    // Поиск активных корзин пользователя
db.carts.createIndex({ session_id: 1, status: 1 }); // Поиск гостевых корзин
```
