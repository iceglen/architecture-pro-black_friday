### Стратегия выявления и устранения «горячих» шардов в MongoDB

---

#### **1. Метрики мониторинга для отслеживания состояния шардов**
Для своевременного выявления дисбаланса предлагаются следующие метрики:

| **Категория**           | **Метрика**                                | **Способ сбора**                                                                 | **Порог срабатывания**                     |
|-------------------------|--------------------------------------------|----------------------------------------------------------------------------------|--------------------------------------------|
| **Нагрузка на шарды**   | CPU, RAM, I/O utilization                  | `mongostat`, Prometheus + MongoDB Exporter, Cloud Monitoring (Atlas)           | >70% CPU/RAM на одном шарде при среднем <30% |
| **Распределение данных**| Количество чанков на шард                  | `sh.status()`, `db.collection.getShardDistribution()`                           | Отклонение >20% от среднего значения       |
| **Запросы**             | RPS (чтение/запись) по категориям          | Агрегация с `$group` по полю `category` + APM-инструменты (Datadog, New Relic)  | 70% запросов к одной категории на одном шарде |
| **Задержки**            | p95 времени выполнения запросов            | `db.currentOp()`, логи MongoDB с включённым `slowms`                            | Рост задержек на 50% относительно нормы   |
| **Дисковое пространство**| Размер данных/индексов на шард             | `db.stats()`, `shard.getShardVersion()`                                          | Неравномерность >30% между шардами         |

**Пример настройки алерта в Prometheus:**
```yaml
- alert: HotShardDetected
  expr: mongodb_shard_chunks{shard="shard0001"} > avg(mongodb_shard_chunks) * 1.3
  for: 5m
  labels:
    severity: critical
  annotations:
    summary: "Горячий шард {{ $labels.shard }}"
    description: "Количество чанков на шарде превышает среднее на 30%"
```

#### **2. Механизмы автоматического перераспределения данных**

##### **2.1. Оптимизация ключа шардирования**
- **Проблема:** Текущий ключ (например, `{ category: 1 }`) создаёт дисбаланс из-за популярной категории «Электроника».
- **Решение:** Использовать **составной хешированный ключ** для равномерного распределения:
  ```javascript
  // Пример для коллекции товаров
  sh.shardCollection("shop.products", { 
    "category": "hashed",  // Хеширует категории для равномерного распределения
    "productId": 1         // Сохраняет локальность для запросов по ID
  });
  ```
  **Эффект:** Запросы к «Электронике» распределятся по разным чанкам, а не сконцентрируются на одном шарде.

##### **2.2. Зонирование (Zone Sharding)**
- **Сценарий:** Если категория «Электроника» критична, выделить для неё отдельные шарды.
  ```javascript
  // 1. Привязать теги к шардам
  sh.addShardTag("shard0001", "ELECTRONICS_HOT");
  sh.addShardTag("shard0002", "ELECTRONICS_COLD");

  // 2. Определить зоны для диапазонов значений
  sh.addTagRange("shop.products", 
    { category: "Electronics", popularity: { $gte: 90 } }, // Горячие товары
    { category: "Electronics", popularity: 100 },
    "ELECTRONICS_HOT"
  );

  sh.addTagRange("shop.products", 
    { category: "Electronics", popularity: { $lt: 90 } }, // Остальные товары
    { category: "Electronics", popularity: 0 },
    "ELECTRONICS_COLD"
  );
  ```
  **Эффект:** Нагрузка от популярных товаров распределяется между несколькими шардами.

##### **2.3. Автомасштабирование и балансировка**
- **Включить встроенный балансировщик** (если отключён):
  ```javascript
  sh.setBalancerState(true);
  sh.enableSharding("shop"); // Убедиться, что балансировка активна
  ```
- **Настроить кастомные правила балансировки** (MongoDB 6.0+):
  ```yaml
  # В конфигурации balancer
  balancer:
    activeWindow:
      start: "02:00"
      stop: "06:00"
    secondaryThrottle: true
    chunkSize: 64  # Уменьшить размер чанка для частой балансировки
  ```

#### **3. Примеры команд для диагностики**
- **Анализ распределения чанков:**
  ```javascript
  use config;
  db.chunks.aggregate([
    { $match: { ns: "shop.products" } },
    { $group: { _id: "$shard", count: { $sum: 1 } } }
  ]);
  ```
- **Поиск «горячих» категорий:**
  ```javascript
  db.products.aggregate([
    { $group: { _id: "$category", count: { $sum: 1 } } },
    { $sort: { count: -1 } },
    { $limit: 5 }
  ]);
  ```
